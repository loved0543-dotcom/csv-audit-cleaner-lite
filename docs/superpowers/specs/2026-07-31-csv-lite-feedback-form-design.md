# CSV Lite 공개 피드백 폼 설계

## 목적

무료 Lite를 실제로 사용한 사람이 성공 결과·문제·질문을 공개 근거로 남길 수 있게
한다. 판매자가 만든 테스트를 고객 후기처럼 바꾸지 않고, 제3자 신뢰가 생길 수 있는
정직한 수집 경로만 만든다.

## 선택한 접근

GitHub Issue Form 한 개를 저장소에 추가하고 README와 기존 v1.0.0 Release에서
연결한다.

- 유형: worked / problem / question
- 제품 버전: 기본 v1.0.0
- 선택 입력: 입력·출력 행 수, 빈 행·중복·실패 수
- 필수 입력: 무엇을 시도했고 무엇을 관찰했는지
- 필수 확인: CSV 원본, 고객정보, 이메일, 로컬 경로, 민감한 보고서를 첨부하지 않음
- 제목 prefix: `[Lite feedback]`
- 별도 이메일·지원 SLA·환불·맞춤 지원 약속은 만들지 않는다.

## 검토한 대안

1. 이메일 피드백: 공개 검증이 어렵고 개인정보·수동 응대 부담이 커 제외한다.
2. GitHub Discussions: 새 운영 공간과 분류 체계를 만들 만큼 현재 사용자 신호가
   없어 제외한다.
3. 자유 이슈 링크: 버전·결과·개인정보 경계가 빠질 가능성이 높아 제외한다.

## 성공 기준

- 공개 저장소에 Issue Form 1개가 렌더된다.
- 폼에서 유형, 버전, 실제 관찰, 선택 수치, 개인정보 금지 확인을 받는다.
- README와 v1.0.0 Release에 폼 링크가 각각 정확히 1회 있다.
- 공개 폼 URL이 로그인하지 않은 HTTP에서 열리고 템플릿명이 보인다.
- 기능·가격·Lite ZIP·릴리스 태그·크기·SHA-256은 바뀌지 않는다.
- 실제 제3자 제출이 생기기 전에는 후기·사용 사례가 생겼다고 말하지 않는다.

## 오류 처리와 검증

- Issue Form YAML을 로컬 파서로 읽고 필수 필드와 개인정보 확인란을 검사한다.
- GitHub가 폼을 렌더하지 않으면 README·Release 링크를 공개하기 전에 원인을
  수리한다.
- 공개 뒤 폼 URL, README, Release, 자산 digest를 각각 다시 확인한다.
